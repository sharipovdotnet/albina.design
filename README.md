# albina.design

Одностраничный сайт дизайнера интерьера: приветственный экран поверх галереи проектов —
непрерывная сетка прямоугольников на белом фоне.

## Стек

HTML, CSS, TypeScript. Сборка — Vite, без фреймворков, CSS-библиотек и UI-китов.
Шрифт Montserrat (начертания 300, 400, 500) самохостится через Fontsource, внешних запросов
за шрифтом нет. TypeScript включён в strict-режиме, вместе с `noUncheckedIndexedAccess`,
`noUnusedLocals` и `noUnusedParameters`.

## Команды

```powershell
npm install
npm run dev        # dev-сервер с hot-reload
npm run build      # tsc --noEmit + сборка в dist/
npm run preview    # локальный просмотр сборки
npm run typecheck  # только проверка типов
```

## Публикация

Сайт живёт на `https://albina.rustamshar.ru/` — субдомене `rustamshar.ru`, зона которого
обслуживается NS-серверами reg.ru. Собирает и выкладывает сайт GitHub Actions
(`.github/workflows/deploy.yml`): push в `main` запускает `npm run build`, и в интернет уходит
содержимое `dist/`. Коммитить сборку в репозиторий не нужно.

Файла `vite.config.ts` в проекте нет и он не нужен: сайт отдаётся с корня домена, а не из
подпапки, поэтому хватает базового `base: '/'` — собранные пути (`/assets/…`, `/images/…`)
и так абсолютные.

Чтобы публикация заработала, в настройках репозитория нужны три вещи: Pages → Source
`GitHub Actions` (не «Deploy from a branch»), Pages → Custom domain `albina.rustamshar.ru`
и разрешённые Actions. У репозитория под приватной видимостью Pages доступен только на платных
тарифах.

DNS-запись для субдомена GitHub описывает так: `CNAME` с именем `albina` и значением
`sharipovdotnet.github.io` (без имени репозитория). Четыре A-записи из документации
(`185.199.108.153`…`185.199.111.153`) — вариант для apex-домена, но работают и на субдомене,
если CNAME почему-то не подходит. Домен в настройках Pages надо сохранить *до* правки DNS:
иначе на освободившийся субдомен сможет сесть чужой репозиторий.

HTTPS включается галочкой Enforce HTTPS в тех же настройках, но не сразу: сначала GitHub
выпускает сертификат Let's Encrypt, а для этого запись уже должна резолвиться. До 24 часов.

## Приветственный экран

`.intro` лежит поверх страницы фиксированным слоем на всю высоту окна: портрет, надзаголовок,
заголовок, прочерчивающаяся линия и абзац. Пока экран открыт, `intro.ts` вешает на `<html>`
класс `is-intro-open` (прокрутка фона под оверлеем заблокирована) и помечает блок `#page` как
`inert`, поэтому Tab и клики под оверлей не уходят.

Экран уходит сам через 10 секунд, раньше — по Esc или по кнопке «Смотреть проекты»
(`.intro__cta`). Оверлей гаснет по классу `is-leaving` — 420 мс, ровно
столько же ждёт код перед удалением блока; при `prefers-reduced-motion: reduce` анимация
и ожидание снимаются, оверлей удаляется сразу. После закрытия фокус переходит на `#main`.
Без JS экран просто не показывается (`<noscript>` в `index.html`): под ним лежит весь контент,
и закрывать его было бы нечем.

Элементы карточки приветственного экрана входят каскадом (`intro-rise`, задержки 80–420 мс,
линия — `intro-draw`). Кнопка выхода — единственная кнопка сайта: hairline-рамка той же линии,
что и под заголовком, без скруглений, с заливкой, входящей слева тем же жестом `scaleX`.
Наведение и `:focus-visible` дают одинаковый отклик — заливка и стрелка, уехавшая вправо.
Портрет кадрируется снизу и гасится радиальной маской по кругу, поэтому
кромка растворяется в белом фоне страницы, а не читается полосами.

## Как устроена сетка

Ячейки разделены отступом 5 px по горизонтали и вертикали, поэтому общую линию они не делят:
рамку в 1 px несёт каждая ячейка, а контейнер своих линий не рисует. Ячейки вертикальные
(3:4). Колонок: одна до 640 px, две до 1024 px, три до 1280 px, пять дальше — десять проектов
ложатся ровно в два ряда. Боковые отступы `main` — 300 px, пока экран не уже ~1364 px, дальше
они уменьшаются пропорционально (`padding-inline: min(300px, 22vw)`); от 1280 px, где
появляется пятая колонка, токен `--main-gutter` падает до 220 px — в прежних полях ячейка
вышла бы 164 px вместо ~200, как при четырёх колонках.

Ячейка — это `<button type="button">` с `id` по слагу проекта и `aria-haspopup="dialog"`:
клик по ней открывает окно галереи. Карточки появляются по очереди: задержка входа считается
от порядкового номера через переменную `--index` (шаг 50 мс).

## Окно галереи

Окно одно на весь сайт — `<dialog id="lightbox">` в `index.html`, содержимое подставляет
`src/ts/lightbox.ts` при клике по ячейке. Нативный `<dialog>` берёт на себя модальность,
`inert` фона, ловушку фокуса, возврат фокуса на ячейку после закрытия и Esc, поэтому своего
кода на всё это нет. Закрыть можно кнопкой и Esc: окно занимает экран целиком, и кликать
по затемнению попросту негде. Пока окно открыто, `html` несёт класс `is-lightbox-open`
(прокрутка фона заблокирована).

Окно растянуто на весь экран (`inset: 0` при auto-размерах) и залито тем же `--surface`,
что и страница: `::backdrop` получает этот же цвет, поэтому экран становится страницей,
а не рамкой вокруг снимка. Внутри две колонки — слева кадр, справа описание проекта; между
колонками нет ни линий, ни другого фона, только поля. С 64rem описание занимает свою колонку
(`clamp(21rem, 32vw, 30rem)`), ниже окно одноколоночное: кадр сверху, описание под ним,
и прокручивается всё окно целиком.

Кадры проекта лежат в поле `photos` (`src/ts/data/projects.ts`), листаются стрелками, ← → и
по кругу; счётчик «Фотография 3 из 12» — живая область `role="status"`, он же озвучивает
смену кадра. Соседние кадры подгружаются заранее, иначе после стрелки кадр стоит пустым.
Кадр показывается целиком (`object-fit: contain`), а поля по краям — та же заливка окна:
в сетке миниатюра кадрируется, в окне снимок виден весь.

Описание проекта — поле `description`, массив абзацев: каждый абзац рисуется отдельным `<p>`
через `textContent`. Текст идёт сразу под заголовком и линией; длинное описание
прокручивается в своей колонке, заголовок и кнопка закрытия остаются на месте. Пустой
список оставляет колонку с одним заголовком.

Серии есть у всех десяти проектов, поэтому окно почти всегда листается: стрелки и счётчик
прячутся только там, где кадр один. Если у проекта нет ни серии, ни обложки (`cover: null`),
в окне стоит подпись «Фотографии проекта скоро появятся». Подготовка файлов и требования к
ним — в `public/images/projects/README.md`, инструмент — `tools/prepare-photos.ps1`.

## Раскраска фотографий

Фотографии в сетке по умолчанию монохромные, цвет возвращает наведение мыши. Клик по ячейке
занят окном галереи, а одно касание не может и раскрасить кадр, и открыть окно, поэтому
раскраски по тапу больше нет: сетка — монохромный указатель, цвет живёт в галерее.

Стили `:hover` спрятаны под `@media (hover: hover)`: на тач-экране они «залипали» бы на
последней тронутой ячейке. При наведении фотография ещё и слегка приближается
(`transform: scale(1.04)`).

Первые пять карточек грузятся с `loading="eager"` — первый ряд виден без прокрутки,
остальные лениво. Атрибутов `width`/`height` у снимков нет намеренно: место под кадр
резервирует `aspect-ratio` у `.project__media`, поэтому фиксированные числа ничего не
добавили бы — сдвига при загрузке нет и без них. Обложки при этом все 1200×1600.

## Что осталось заглушками

- Контакты в `<footer>` — в `index.html` стоит TODO; пока в подвале копирайт и подпись
  разработчика, а телефон и Telegram живут в шапке.
- Текст приветствия — заготовка, TODO заменить на текст от Альбины.
- Названия проектов в сетке не показываются: подписи из ячеек убраны, поле `title`
  в данных работает на `alt` фотографии («Интерьер: …») и на заголовок окна галереи.
- Описания проектов — черновики, собранные по фотографиям: в них есть только то, что видно
  в кадрах, без площадей, годов и планировок. Место правки — поле `description`
  в `src/ts/data/projects.ts`.
- Водяные знаки и QR-коды: часть исходников пришла с логотипом студии и QR-кодом в углу —
  они видны и на обложках, и в окне галереи. Если нужны чистые кадры, их надо переснять
  или прислать версии без знаков, а потом прогнать `tools/prepare-photos.ps1` заново.
- Обложки выбраны автоматически (первый вертикальный кадр, если не указан явно) — вкусовая
  правка делается одним параметром `-Cover` и повторным прогоном инструмента.

## Скиллы проекта

`.dsh/skills` — восемь скиллов:

- **Дизайн:** `frontend-design` — направление, типографика с кириллицей, палитра, сдержанный motion.
- **Код:** `vanilla-web-standards` — семантика, CSS-токены и слои, типизированный DOM.
- **Аудит интерфейса:** `web-design-guidelines` — соответствие Web Interface Guidelines.
- **Доступность:** `accessibility` — WCAG 2.2: контраст, фокус, клавиатура, alt-тексты, зум.
- **Производительность:** `performance` и `core-web-vitals` — бюджеты по весу, LCP/INP/CLS, шрифты и изображения.
- **Разметка для поиска:** `schema-markup` — JSON-LD, `LocalBusiness`/`InteriorDesigner`.
- **Поведение агента:** `karpathy-guidelines`.

`accessibility`, `performance` и `core-web-vitals` предпочитают живую сессию Chrome DevTools MCP, но
имеют явный фолбэк на Lighthouse CLI, axe и ручные проверки, поэтому работают без внешних
инструментов. Происхождение, даты и лицензии сторонних скиллов — в `.dsh/THIRD-PARTY.md`.

## Визуальная проверка

Вёрстку проверяем скриншотом живого рендера, а не по коду. Chromium не запускается внутри
ограниченной песочницы DSH: он открывает именованные каналы (mojo), а они в confined-режиме
запрещены, поэтому запуск браузера требует разового расширения прав до `danger-full-access`.

Dev-сервер слушает IPv6-петлю, поэтому обращаться к нему нужно по `http://localhost:5173/`
(`127.0.0.1` не отвечает). Каталог `.preview/` — рабочий, из git исключён.

```powershell
# 1. поднять dev-сервер в отдельном процессе
npm run dev

# 2. снять скриншот 1440x1000 в .preview/
& "C:\Program Files\Google\Chrome\Application\chrome.exe" --headless=new --disable-gpu `
  --hide-scrollbars --no-first-run --disable-crash-reporter `
  --user-data-dir=".preview\chrome-profile" --window-size=1440,1000 `
  --virtual-time-budget=8000 --screenshot=".preview\verify-1440.png" "http://localhost:5173/"
```

Первый кадр занимает интро-заставка из `src/ts/intro.ts` — она держится 10 секунд, поэтому
чтобы увидеть галерею, нужен `--virtual-time-budget` побольше или снимок после её
проигрывания. Способ без расширения прав: запустить браузер самому с
`--remote-debugging-port=9222` и дать агенту подключиться по CDP.

Две ловушки, проверенные на практике. Пути в `--user-data-dir` и `--screenshot` лучше давать
абсолютными: с относительными запуск под расширенными правами завершался молча, без файла и без
ошибки. И `--window-size` уже 500 px headless не соблюдает — окно клампится к 500 px, а кадр
обрезается по запрошенной ширине, из-за чего текст на снимке «уезжает» за край. Мобильные
ширины снимаются через CDP (`Emulation.setDeviceMetricsOverride`), а не флагом окна.
